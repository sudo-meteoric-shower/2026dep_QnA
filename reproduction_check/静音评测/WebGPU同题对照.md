原九题、六道留出题均沿用已有材料及题目。《控制工程导论》第 4 版书页 2～10 的 35 个分块用于教材六题。在同一题目上比较两条提示时使用同一份索引。各表格单元的完整作答均时含检索、生成和清洗，包括答错的题，起点为提交文字问题，终点为界面返回完成。录音、播报、首次加载与预建索引另计。本次复测的题目均已使用过。

**评分口径。** 使用核心答案计分，按题干已给出的单位理解简短数值，同时检查最终答复有无自相矛盾。1.7B 原指令的计算题算出 150 后又声称资料未提及，计错。1.7B 简答的退出备用模式题正确提取 11 伏和 3 秒，但未说全“达到或超过”。如果该题必须给出完整比较关系，则默认组合原九题为 8/9。教材简答错在函数记录仪，把电量随时间变化答成记录笔位移。开环控制题三项条件均有，精度条件使用英文 “not very high”，内容计对，中文表达仍有缺点。0.6B 原指令的开环控制题末句列全三项，按同样口径计对；其简答提示多次错误拒答。

**显卡证据。** 问答管线显式使用 WebGPU，请求高性能适配器，模型就绪报告记录 NVIDIA Lovelace。评测逐题记录生成期间向 `GPUQueue.submit` 提交的次数。各题均为正数。ORT 报告有部分节点分配给其他执行后端，GPU 利用率为整机采样。完整对照各批次均以静音浏览器运行，无外网请求，未启用实物麦克风或扬声器。模型文件沿用本机下载版本，新增 Git 提交仅含代码、说明与数据。

**最终默认配置。** GPU 分支默认选择 Qwen3-1.7B 和简答提示。若手选 0.6B 则使用其正确数更高的原指令。未经提示或模型替换，从默认入口重新跑原九题及六道留出题，与候选配置的原始回答逐题相同。默认入口两组完整均时分别为 **1.64 秒、1.62 秒**，六题首段平均约 **1.00 秒**。对照前轮狂暴模式的 1.7B、CPU 16 线程，六题为 4/6、33.08 秒，本次为 6/6、1.62 秒。后端、量化权重和提示均有变化，这组对照衡量整套配置。硬件适配器选择参照 [ONNX Runtime WebGPU](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)。

正式结果摘要及各题作答时间、GPU 命令数、显存采样见 [GPU 评测摘要](gpu-results.json)。[默认原九题](candidate-gpu-default.json)与[默认六题](candidate-fresh-gpu-default.json)包含原始和清洗后的答案。教材逐题数据以题号和评分保存在摘要中，教材原文及包含检索片段的明细保留在本机。

一次教材复测因系统可用内存降至 4048 MiB 触发保护，当时空闲显存最低 4623 MiB。释放该批次的测试浏览器并补充关闭逻辑后，同一教材批次完整重跑，12 条回答均与初次对照一致。

## 复现

在仓库根目录用 PowerShell 执行下列命令。每批启动前读取系统内存和显存，整机空闲显存至少 6144 MiB 才启动 GPU 测评，运行时连续两次可用内存低于 4096 MiB 或显存低于 1024 MiB 会停止。注意独立结果标签，避免覆盖历史批次。

```powershell
node reproduction_check/verify.cjs --compare=candidate --webgpu --monitor-resources --wasm-threads=4 --result-tag=my-gpu-nine
node reproduction_check/verify.cjs --compare=candidate --webgpu --monitor-resources --wasm-threads=4 --fresh --result-tag=my-gpu-six
```

比较模型时另加 `--model=qwen3_06b` 或 `--model=qwen3_17b`，比较提示时另加 `--prompt-probe=original` 或 `--prompt-probe=faithful`。教材先依照[教材准备说明](教材提示词与BGE对照.md)从本机教材准备材料，再加 `--study-set=control --study-emb=small`。该模式逐题交替测试原指令和简答。
