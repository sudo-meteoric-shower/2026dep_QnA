# 1.7B 证据顺序、简答指令与 WASM 线程

在 1_7_try 用 Qwen3-1.7B q8、现有 WASM 后端和静音浏览器测试。改动只由评测脚本注入页面，每次独立启动前检查显存和系统内存。正式页面使用 4 线程。RTX 4060 Laptop GPU 可用显存为 7957 MiB，试验推理运行在 CPU。

## 证据顺序与简答指令

四道诊断题为冲洗时长、锁阀条件、在用仪器编号和备用机充电。完整上下文组取自上一轮同题评测。证据顺序将排名第一的完整片段移到问题前，按提示中的顺序编号。简答组只改最后一句指令，要求第一句给答案，保留全部条件和单位。论文指出证据位置会改变模型表现，本轮在约 245 token 的短输入上做初步验证。[Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)

| 配置 | 内容正确 | 平均生成 token | 平均完整时间 |
| --- | ---: | ---: | ---: |
| 原顺序与原指令 | 2/4 | 60.75 | 62.32 秒 |
| 最相关片段移到问题前 | 4/4 | 33.00 | 87.75 秒 |
| 第一句给答案 | 3/4 | 25.75 | 38.23 秒 |

冲洗题标准值为连续 25 秒，简答组写成“不低于二十五秒”，记错。简答组答对在用仪器编号，但先引用备用仪器，论据不匹配。证据顺序组按内容计分，编号有多余符号，模型回答中的资料编号与页面原引用顺序可能不符。后续若采用顺序实验，需要保持引用编号固定并扩大未见题覆盖。耗时跨独立运行，不把总耗时差直接归给候选。生成 token 减少是可复查的结果。

## 线程数

同一道十五分钟题各冷启动测一次。三组提示均为 225 token，生成均为 4 token，最终回答均为 15 分钟。测试时可用系统内存不同。

| WASM 线程数 | 首片段 | 完整回答 |
| --- | ---: | ---: |
| 2 | 13.58 秒 | 14.39 秒 |
| 4 | 12.57 秒 | 13.56 秒 |
| 8 | 9.54 秒 | 10.41 秒 |

8 线程是单次样本中的提速候选，后续应在固定题型上重复并记录内存和长尾延迟。增加浏览器进程可能增加并发吞吐，但独立模型实例会占用更多内存。用 Worker 可以减少界面卡顿，模型计算速度仍需单独测量。[2 线程](candidate-threads-2.json) · [4 线程](candidate-threads-4.json) · [8 线程](candidate-threads-8.json) · [ONNX Runtime Web 性能诊断](https://onnxruntime.ai/docs/tutorials/web/performance-diagnosis.html)

WebGPU 是另一个执行后端，教师书面要求为 WASM。4060 的显存值得做单独实验，能否提速取决于模型导出的算子、数据类型、浏览器适配器及峰值显存。此轮只验证 CPU WASM。[ONNX Runtime WebGPU](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)
