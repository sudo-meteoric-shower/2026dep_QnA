## 编码和生成

三个单句用例的实际输入分别为 81、81 和 90 个 token，与模板直接编码逐项相同。输入解码可见完整的 system、user 和 assistant 起始标记。浏览器端的分词器类名是压缩包中的 Ye，模型类型为 qwen2，文件目录为 Qwen2.5-1.5B-Instruct。每组完整输入和输出 ID、attention mask、原始流式文本、管线返回文本和清洗后文本均附在 JSON。

| 单句证据 | 四线程原始生成 | 单线程结果 |
| --- | --- | --- |
| 设备启用前需充电十五分钟 | 生成“五分钟”，随后写出无关耗电题 | 输入、输出 token 和文本逐项相同 |
| 同一句替换为四十分钟 | 生成“40 分钟” | 输入、输出 token 和文本逐项相同 |
| 校验代号为松柏三七 | 生成“五九八零四二一六”，并虚构资料编号 | 输入、输出 token 和文本逐项相同 |

三题的流式文本、管线返回文本和新增 token 解码文本逐项一致，都到达 80 token 上限。十五分钟和代号在首个回答片段中已错。单线程对照排除了本次差异由线程数设置造成的解释。仅凭本轮结果仍无法区分上游 ONNX 转换或量化误差、模型本身对提示的敏感性，以及两种线程设置共用的 WASM 执行问题。

## 增加上下文与修复

四十分钟题只增加同段邻句时，模型在列表中答出了“40 分钟”，旧清洗将整份列表截掉。增加两段无关资料后，模型开始谈文本生成技术，偏差发生在清洗前。修复让只有套话的列表引子让位给前最多三项正文，再应用既有的句数和字数限制。两组上下文在修复前后生成的原始文本和输出 token 均逐项相同，同段邻句用例从空泛引导语恢复为含“40 分钟”的答案。干扰资料用例仍然答错。

本机可用显存为 7957 MiB，四组诊断取样启动前可用内存分别为 12298、12820、13198、13017 MiB。浏览器在四组诊断中均记录 0 条控制台错误、0 次失败请求、0 次外部请求。
